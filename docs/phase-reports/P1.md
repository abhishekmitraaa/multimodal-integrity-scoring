# Phase 1 report: capture app, server log, replay

Date: 2026-09-26. Status: **awaiting the lead's approval before P2.**

P1 delivers a working end-to-end pipeline. The Monaco exam app captures keystrokes, edits,
clipboard, focus and Run/Test events. The server orders them, hash-chains them and stores them
encrypted in an append-only table. Replay rebuilds the code exactly, and a minimal reviewer page
scrubs through it. All acceptance tests pass in Chromium and Firefox. They pass in WebKit too, except
clipboard capture, which cannot be measured in that build (see "What is weak").

All test data in this phase is **synthetic**: scripted input, participant kind `synthetic`. No real
participant data exists.

What the acceptance tests cover (SPEC 13, P1 row):

- **Ordering.**
  - In-order, duplicate, out-of-order (nack, then recovery) and reconnect-with-overlap batches all
    give gapless `server_seq`, with client events in `client_seq` order.
  - A stale batch from a reloaded page is refused.
  - A newer socket supersedes an older one.
- **Hash chain.**
  - Editing any single field of any record is detected at that index.
  - So are insertion, deletion and reordering.
  - A row modified directly in PostgreSQL, with the trigger disabled, is caught by `/verify`.
  - A full chain recomputation is caught only against a kept head hash. This is the documented P1
    gap.
- **Storage.**
  - UPDATE, DELETE and TRUNCATE on `events` and `access_log` are refused by triggers.
  - Erasure works through its guarded path and leaves a tombstone with no pseudonym.
  - Event payloads are encrypted at rest: no plaintext code or event type appears in the bytes.
  - Ciphertexts are bound to their row.
- **Replay.**
  - Server and client replay equal every snapshot, in all three browsers.
  - This covers typed code, paste, undo, redo, multi-cursor edits, non-BMP text (`π😀`) and a page
    reload mid-session.
- **Capture coverage** (Chromium and Firefox):
  - covered: segment start and end, keydown/keyup, content changes, snapshots, Run/Test, submit,
    focus, blur, copy (problem panel and editor), cut, paste, cursor, drop (blocked), visibility,
    clock sync, `ws_open`/`ws_close`.
  - `composition` (IME) and `client_notice` are implemented but not exercised: Playwright cannot
    drive an IME, and no policy mismatch occurred.
- **Privacy guards.**
  - Real participants are refused while `real_collection_enabled: false`, and 18+ confirmation is
    required.
  - `KeyboardEvent.key` never reaches the server.
  - Staff reads are access-logged, and the reviewer role cannot read the access log or erase data.

## What works

- **Capture to replay.** The pipeline works end to end in three browser engines, both plain and
  cross-origin isolated. Pyodide Run/Test also works in a Web Worker under COOP/COEP.
- **Server as source of truth.** It assigns order and time, rejects floats and malformed events,
  keeps an append-only, encrypted, hash-chained log, and can prove a stored log was not edited row
  by row.
- **Editor policy enforced twice.** Text-inserting Monaco features are never loaded (D-023), and a
  self-check reports any option Monaco didn't apply.
- **Real collection cannot start by accident.** Real participants are refused until ethics approval
  flips one config switch.

## What is weak

1. **Safari is unverified.**
   - Playwright's WebKit on Windows reports a macOS user agent but uses Windows key handling. Monaco
     then binds Cmd shortcuts, and copy/paste never fire.
   - Clipboard capture and every Safari measurement need a real Mac.
   - The same quirk made our user-agent OS guess record `macos`, so `os_family` from the user agent
     is unreliable.
2. **Timing semantics with real keyboards are unmeasured.** All measurements used synthetic CDP
   input. Whether `event.timeStamp` is the OS input time or the dispatch time needs a manual test
   with a real keyboard.
3. **Automation looks trusted.** Browser-automation keystrokes are `isTrusted = true`, so that flag
   can't flag auto-typers (A2/A3). OS-level injection on Windows was not tested.
4. **Replay can bypass the policy.** The find widget's replace toggle is still clickable, and
   replace-all edits arrive as `cause: unknown`.
5. **Change causes are client hints only.** The server-side canonical recomputation is deferred to
   P3.
6. **The chain is unsigned.** Anyone with database write access who recomputes the whole chain is
   caught only if the participant kept their head hash.
7. **Timer resolution without isolation is coarse.** Firefox and WebKit give 1 ms without COOP/COEP.
   That is probably fine for 50–200 ms keystroke intervals, but it is a covariate, and it is 50×
   coarser than the isolated origin.
8. **The consent screen is a DRAFT.** It waits on the faculty guide's answers (Q4) and ethics
   approval.
9. **Disk encryption on this laptop is unknown.** The check needs admin rights. Field-level
   encryption protects event payloads regardless.
